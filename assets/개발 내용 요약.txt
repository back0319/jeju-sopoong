
최종 확정사항

1. 전체 이용 흐름

입장 → 공통 QR 접속 → 언어 선택 → 안내/소개 → 설문 → 원물 확인 → 김밥 구성 선택 → 주문 완료 → 카운터에서 주문 확인·결제 → 기본 키트 + 추가 토핑 수령 → 자리에서 직접 김밥 만들기 → 식사 → 퇴장

* 완성된 김밥을 판매하는 것이 아니라 고객이 직접 김밥을 만드는 체험형 운영
* 직원 설명은 최소화하고 모바일 웹을 중심으로 안내
* 모르면 직원에게 질문할 수 있도록 운영

2. QR

* 테이블마다 별도 QR을 만들지 않음
* 공통 QR 1개로 통일
* 테이블 번호도 사용하지 않음
* QR 접속 후 고객이 직접 주문 과정을 진행
* 최종 주문 완료 시 주문번호 부여
* 주문번호를 이용해 현장에서 주문 내용을 확인

3. 모바일 웹

첫 화면에서 언어 선택을 진행.

언어에 따라 안내 콘텐츠가 달라질 수 있도록 구성.

주요 콘텐츠:

* 매장 이용 방법
* 브랜드/매장 소개
* 제주 생산자 소개
* 제주 원물 및 특산물 소개
* 원물 관련 영상
* 김밥 재료 선택
* 추가 토핑 선택
* 주문 확인

※ 이용방법 자체를 설명하는 별도 안내물은 웹에 넣기보다 매장에 부착하는 방향.

4. 영상

* 생산자 및 원물 소개 영상 활용
* 영상은 유튜브에 업로드 후 웹에서 연결
* 별도의 영상 DB 구축은 하지 않음
* 언어별 유튜브 링크를 연결하는 방식

5. 주문 방식

* 기본 김밥 키트를 미리 준비
* 고객이 모바일에서 필요한 재료/토핑을 선택
* 주문 내용은 DB에 저장
* 고객이 카운터에서 주문 결과 화면을 보여줌
* 직원이 주문 내용을 확인한 뒤 결제
* 결제 후 기본 키트와 추가 토핑을 제공
* 고객이 직접 김밥을 제작

6. 기본 김밥 구성

기본 재료는:

* 김
* 밥
* 계란
* 햄
* 단무지
* 맛살

단, 재료를 개별적으로 넣고 뺄 수 있는 선택 구조를 적용하는 방향으로 확정.

특히 비건/특정 식재료 제한 고객을 고려해 재료 선택 기능을 제공.

7. 추가 토핑

제주 원물을 활용한 추가 토핑을 선택할 수 있음.

기존 논의 기준 주요 원물:

* 고사리
* 뿔소라
* 당근
* 제주 돼지고기 등

원물 추천 기능은 유지하되, 복잡한 MBTI식 캐릭터 추천은 하지 않음.

→ 원물 중 추천 원물 2개 정도를 제시하는 수준으로 정리.

8. 주문번호/현장 제공

* 주문 완료 시 주문번호 생성
* 주문번호를 통해 현장에서 고객 주문 확인
* 주문 완료 순서대로 무조건 제공하는 방식은 아님
* 고객이 카운터에 도착해서 주문번호를 확인하면 해당 주문을 제공
* 따라서 3번 주문자가 먼저 와서 받을 수도 있음

9. 관리자 페이지

관리자 페이지를 구축.

주요 관리 기능:

* 주문 내역 확인
* 주문번호 확인
* 고객이 선택한 재료/토핑 확인
* 주문 상태 관리
* 재료 품절(SOLD OUT) 처리
* 재료별 수량 관리
* 통계/데이터 확인

10. 재료 재고 관리

추가 토핑은 초기 수량을 관리자에서 입력.

예:

* 뿔소라 20인분 설정
* 주문이 들어올 때마다 수량 차감
* 잔여 수량에 따라 자동으로 품절 처리

즉, 재고 수량 기반 SOLD OUT 기능을 적용.

11. 데이터 수집

단순 주문뿐 아니라 고객 데이터를 축적.

확정적으로 필요한 데이터:

* 주문번호
* 주문한 기본 김밥
* 추가한 토핑
* 재료 선택/제외 정보
* 언어
* 국가 등 기본 고객 정보
* 설문 응답 데이터
* 설문 완료 여부

이를 통해 향후
“어떤 유형의 고객이 어떤 재료를 선택했는가”를 분석할 수 있도록 함.

12. 설문

기존 MBTI 방식의 여행자 유형 테스트는 하지 않음.

대신 설문은 고객의 기본적인 특성과 미식 취향을 파악하는 방향으로 구성.

논의된 기본 정보:

* 국적/어디서 왔는지
* 연령
* 성별
* 미식 취향
* 먹지 못하거나 선호하지 않는 음식

설문 결과를 복잡하게 추천 알고리즘과 연결하지 않고, 데이터 수집 및 고객 이해 목적으로 활용.

13. 알레르기/식재료 제한

고객이 먹지 못하는 식재료를 선택할 수 있도록 함.

특히:

* 계란
* 햄
* 맛살
* 뿔소라 등

식재료 제한 정보를 받을 수 있도록 구성.

다만 알레르기 관련 세부 정책은 추후 실제 운영하면서 보완하는 것으로 함.

14. 라면·음료·굿즈

김밥 외에 추가 판매 상품으로:

* 라면
* 음료
* 굿즈
* 향후 디저트

등을 추가할 수 있도록 구조를 만들어 둠.

관리자에서 향후 메뉴를 추가/활성화할 수 있는 구조로 개발.

15. 패키지

김밥 기본 가격은 5,000원.

논의된 패키지:

* 김밥 5,000원
* 라면
* 음료/굿즈 등을 포함한 15,000원 패키지

핵심은 김밥 주문을 완료한 뒤 라면·음료·굿즈를 추가 구매하도록 유도하는 구조.

추가 구매 시 총 금액이 자동 계산되도록 함.

16. 현장 운영

운영은 최대한 셀프서비스 + 최소한의 직원 소통으로 진행.

기본적으로:

* 고객이 QR을 직접 찍음
* 웹에서 직접 선택
* 카운터에서 주문 확인
* 결제
* 키트 수령
* 직접 제작

직원은 필요한 경우 설명하거나 주문을 도와주는 방식.

17. 웹 장애 대비

웹/서버/인터넷 장애에 대비한 비상 운영 방법 필요.

* 종이 주문서 등 오프라인 대응 수단 준비
* 매장 와이파이 안내 필요
* 웹이 작동하지 않아도 최소한 주문을 받을 수 있어야 함

18. 안전관리

안전 문제를 중요하게 고려.

특히:

* 미끄럼 사고
* 컵/식기 파손
* 식중독
* 뜨거운 물/라면 기계
* 어린이 뛰어다님
* 2층 이동 문제

등을 고려해 운영해야 함.

라면 기계와 뜨거운 물을 2층에서 사용하는 경우 안전관리 인력 배치가 필요하다는 점이 확인됨.

19. 2층 운영

2층은 직원이 관리할 필요가 있음.

특히 뜨거운 라면 기계를 이용하기 때문에:

* 뜨거운 물을 들고 계단 이동하는 방식은 지양
* 2층에 관리 인력을 두는 방안 검토
* 어린이 안전관리 필요

20. 테스트 일정

9월 10일까지 테스트용 컴퓨터/모니터 환경을 구비

필요 장비:

* 컴퓨터 또는 노트북
* 모니터
* 키보드
* 마우스
* HDMI 등 연결 장비

웹 기반 시스템이므로 고사양 컴퓨터는 필요하지 않음.

21. 개발 일정

9월 14일 전까지 1차 완성

→ 10일까지 테스트 환경 구축
→ 1차 개발본으로 실제 테스트
→ 문제점 발견 시 수정
→ 오픈 후에도 운영하면서 개선



한 줄로 정리하면

“공통 QR 하나로 고객이 언어 선택 → 매장·제주 원물 소개 → 설문 → 재료·토핑 선택 → 주문번호 생성 → 카운터에서 주문 확인·결제 → 키트 수령 → 고객이 직접 김밥 제작”하는 셀프 체험형 시스템으로 확정되었고, 관리자에서는 주문·재고·품절·고객 데이터를 관리한다.

그리고 MBTI식 여행자 테스트, 테이블별 QR, 테이블 번호, 복잡한 AI 추천 기능은 최종안에서 제외된 것으로 보면 됩니다.
